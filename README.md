# 확장성을 고려한 Custom Select 컴포넌트 시스템

단일 선택, 다중 선택, 트리 구조 선택 등 다양한 형태의 Select를 구현하기 위해 공통 기능과 선택 로직을 분리하여 컴포넌트를 구성했습니다.

---

## 설계 과정

처음에는 하나의 Select 컴포넌트에서 모든 기능을 처리하는 구조를 고려했습니다. 하지만 단일 선택, 다중 선택, 트리 선택은 필요한 상태와 동작 방식이 서로 달라 기능이 추가될수록 조건문이 많아지고 관리가 어려워질 수 있다고 판단했습니다. 

따라서 드롭다운의 공통 기능은 `BaseSelect`로 분리하고, 단일 선택 제외한 Select들은 확장하여, 선택 방식에 따른 로직을 각각의 컴포넌트에서 구현하도록 구성했습니다. 이 구조를 통해 공통 기능 수정 시 영향을 최소화하고, 
새로운 형태의 Select가 필요할 경우 기존 구조를 재사용할 수 있도록 설계 했습니다. 또한 과제에서 제공된 공통 인터페이스를 유지하면서 다양한 데이터 구조를 사용할 수 있도록 제네릭(Generic) 타입을 적용했습니다.

---

## 컴포넌트 구성 및 역할

| 컴포넌트 | 주요 기능 및 역할 |
| :--- | :--- |
| **BaseSelect** | **드롭다운 UI와 공통 동작 담당**<br/>• 드롭다운 열기/닫기 상태 관리<br/>• 외부 영역 클릭 시 닫기 처리<br/>• 공통 레이아웃 및 스타일 제공<br/>• 웹 접근성을 위한 aria 속성 적용 |
| **MultiSelect** | **다중 선택 로직 담당**<br/>• 선택 항목 추가 및 제거<br/>• 선택 상태 배열 관리 |
| **TreeSelect** | **트리 구조 선택 로직 담당**<br/>• 재귀 컴포넌트를 이용한 계층형 트리 렌더링<br/>• 부모와 자식 노드 간의 상태 동기화<br/>• 트리의 시각적 뎁스에 맞춘 선택 결과 정렬 |

## TreeSelect 구현 상세

트리 구조에서는 부모와 자식의 선택 상태가 서로 영향을 주기 때문에 이를 양방향으로 처리하는 로직을 구현했습니다.

* **하위 노드 동기화 (하향식)**
  부모 노드를 선택하면 모든 자식 노드가 함께 선택되고, 부모를 해제하면 자식 노드도 함께 해제됩니다. 이를 위해 특정 노드의 모든 자손 노드를 재귀적으로 탐색하여 상태를 일괄 변경하도록 구현했습니다.
* **부모 노드 동기화 (상향식)**
  자식 노드가 모두 선택된 경우 부모 노드를 자동으로 선택 상태로 변경하고, 일부라도 해제되면 부모 노드도 해제되도록 구현했습니다. 트리 구조를 순회하면서 부모의 상태를 다시 계산하는 방식으로 처리했습니다.
* **선택 결과 정렬**
  선택된 항목은 사용자가 클릭한 순서가 아닌 실제 트리의 표시 순서(깊이 우선 탐색 기준)를 기준으로 정렬하여 반환하도록 구현했습니다. 이를 통해 선택 결과 텍스트가 화면에 보이는 노드 순서와 일치하도록 UX를 개선했습니다.

## 💡 구현 중 해결한 문제 (Troubleshooting)

### 1. 의도치 않은 드롭다운 닫힘 방지
초기화 버튼이나 트리 내부 노드를 클릭할 때 클릭 이벤트가 상위 요소까지 전파되면서 드롭다운이 닫히는 문제가 있었습니다. 이를 해결하기 위해 클릭 이벤트가 발생하는 필요한 위치에 `e.stopPropagation()`을 적용하여 이벤트 전파(Bubbling)를 차단했습니다.

### 2. 외부 클릭 감지 이벤트의 메모리 관리
드롭다운 외부를 클릭하면 창이 닫히도록 구현하기 위해 전역 `document`에 `mousedown` 이벤트를 등록했습니다. 하지만 이벤트가 계속 남아 있으면 불필요한 이벤트가 계속 남아 있을 수 있으므로, 드롭다운이 열려 있을 때만 이벤트를 등록하고 닫히거나 언마운트될 때 즉시 이벤트를 해제하여 메모리 누수를 방지했습니다.

```typescript
useEffect(() => {
  const handleClickOutside = (event: MouseEvent) => {
    if (
      containerRef.current &&
      !containerRef.current.contains(event.target as Node)
    ) {
      setIsOpen(false);
    }
  };

  // 드롭다운이 열려있을 때만 이벤트 등록
  if (isOpen) {
    document.addEventListener("mousedown", handleClickOutside);
  }

  // 클린업 함수를 통한 이벤트 정리
  return () => {
    document.removeEventListener("mousedown", handleClickOutside);
  };
}, [isOpen]);
```
### 3. 트리 노드 선택 상태의 양방향 동기화
트리 구조에서 부모와 자식의 선택 상태를 일관성 있게 유지하는 부분이 가장 복잡했습니다. 특히 자식 노드 선택 상태가 변경될 때 부모 노드의 상태를 다시 계산해야 했고, 반대로 부모 노드를 선택할 경우 모든 자식 노드의 상태도 함께 변경되어야 했습니다. 이를 해결하기 위해 재귀 탐색 알고리즘을 적용하여 상향 및 하향 방향 모두 상태가 정확히 동기화되도록 구현했습니다.
### 4. 트리 렌더링 방식에 대한 고민

트리 구조를 렌더링할 때 데이터를 평탄화한 뒤 처리하는 방식과 재귀 컴포넌트를 사용하는 방식을 모두 고려했습니다.

평탄화 방식은 리스트 가상화 적용이 용이해 대용량 데이터에서 성능상 이점이 있습니다. 다만 이번 과제에서는 데이터 규모가 크지 않았고, 트리 선택 기능 구현이 더 중요한 요구사항이라고 판단했습니다.

특히 부모-자식 노드 간 선택 상태를 동기화하는 로직이 핵심이었기 때문에, 트리 구조를 그대로 유지하면서 구현할 수 있는 재귀 컴포넌트 방식을 선택했습니다.

이를 통해 데이터 구조와 UI 구조를 동일하게 가져갈 수 있었고, 부모/자식 노드의 선택 상태를 처리하는 로직도 비교적 직관적으로 구현할 수 있었습니다.
